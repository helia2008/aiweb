## 这个活到底烦在哪

行政和人事手上，总有一堆只有你会的内部系统操作：报销单怎么提、OA 流程走哪个入口、办公用品在哪申领、门禁权限怎么开、CRM 里客户信息怎么录。

每来一个新人，你都得从头教一遍。教一遍四十分钟，教到第三个人你会发现——**你自己讲的三遍还不一样**。写在 Word 里的操作手册呢？系统一改版就过时，你也不知道该改哪一页，最后新人拿着过期文档来问你，你还是得现场教。

难的不是操作本身，那些步骤你自己两分钟就点完了。难的是这三件事：

- **把肌肉记忆变成步骤**：你闭着眼都能走完的流程，说出来总是"就点那个……然后……"
- **保持一致性**：对张三讲的和对李四讲的版本不一样，出问题了都说是你教的
- **跟上改版**：系统改一个按钮的位置，你脑子里更新了，文档没人更新

**难点是"把你脑子里的东西变成别人能照着做的东西"，而且每次来人都要重来。** 录一遍给它看，你只负责演示和最后把关。

## 要准备什么

- **已登录的 Chrome 或 Edge**：要录的那个内部系统，你自己先手动登录一次，开着就行
- **浏览器自动化技能**：让桌面 Agent 帮你装，你唯一要手动的是在弹出的商店页点一下"获取 / 安装"，装完在扩展图标上确认显示"已连接 / 运行正常"
- **一份文档模板或旧版说明**：哪怕是只有标题和编号的空白骨架也行。**不给模板，它会自己设计一套排版**，跟你部门的其他文件对不上
- **你自己先在心里走一遍流程**：不用写出来，但得知道总共几步、到哪算结束。**这一步决定你会不会录漏**

## 一步步怎么配

**第一步：装扩展（唯一要你手动的一步）**

让桌面 Agent 帮你装浏览器自动化技能，它能自动跑的都会跑完。你在商店页点"获取"，装完确认显示"已连接 / 运行正常"。**没看到这几个字就别往下走。**

**第二步：开录制**

点浏览器右上角的扩展图标 → 快捷功能 → 操作录制 → 填两个东西：这次任务的**主题**（比如"报销单提交流程"）和**起始网址**。

**第三步：把生成的指令交给桌面 Agent**

它会给你一段录制提示词，复制进桌面 Agent 对话框。它会单独开一个已登录的浏览器窗口，上面提示"正在录制你的操作"。

**第四步：按平时习惯完整演示一遍**

**平时怎么点，这次就怎么点。不要刻意放慢，不要边点边解释。** 演示完点"结束"，它会把整个过程存成一份流程记录文件。

**第五步：让它把记录整理成 SOP 文档**

套上你给的模板，输出一份能直接发给新人的操作说明。

**第六步：你自己当新人，照着文档走一遍**

这步不能省。走不通的地方当场改掉。

## 直接能抄的指令

```
请用浏览器自动化技能，用"操作录制"帮我做一份新人操作说明。

【要录的流程】
（主题）：报销单提交流程
（起始网址）：（填内部系统的登录后的首页地址）

【录制】
我会按平时的习惯完整演示一遍。请记录我进的每个页面、点的每个按钮、
填的每个字段，以及页面之间的跳转顺序。

【演示结束后，整理成文档】
输出一份 Markdown 操作说明，结构如下：

# 报销单提交流程（适用版本：XX / 最后核对日期：YYYY-MM-DD）

## 前置条件
（需要什么权限、什么账号、什么材料，没有就写"无"）

## 操作步骤
1. 打开【页面名称】，点击【按钮/链接的原文名称】
2. ……
每一步只写一个动作。涉及填写的，写清填什么、格式要求、
哪些是必填。有分支的（比如"有发票/无发票"）单独拆成 2.1、2.2。

## 常见卡点
（我在演示中停顿超过 5 秒、回退、或重复操作的地方，单独列在这里，
并注明卡在哪一步。判断不了的就写"此处演示有停顿，待人工确认"）

## 做完怎么确认
（流程走完后，在哪能看到"成功"的标志）

【要求】
- 按钮和菜单名必须写页面上显示的原文，不要概括成"点击相关按钮"。
- 不要写任何演示过程中我没实际操作的步骤。
- 演示里出现的真实姓名、工号、金额、客户名，一律替换成示例值
  （张三 / EMP001 / ¥100.00 / 示例客户）。
- 判断不了的地方标注"待人工确认"，不要猜、不要补充"通常的做法"。
- 文档头部必须写清适用版本和最后核对日期。
```

## 我踩过的坑

**坑一：演示到一半就点了"结束"，后半段步骤全丢了，它还不会提醒我。** 我以为录完了，出来的文档到第三步就断了。原因是它只记录你录到的部分，**不知道你心里的流程还有几步**。解法：录之前先在心里把流程走一遍（几步、到哪算完），录完对照着检查一遍再点结束。多花 30 秒，省一次重录。

**坑二：我怕它看不懂，录的时候刻意放慢、边点边解释，结果文档里塞满无关内容。** 它记录的是页面和点击序列，你多余的解释和来回切换会被当成步骤写进去，出来的操作说明又长又乱。解法：**平时怎么点，这次就怎么点，不要加戏。** 那些"为什么这一步要这么选"的经验，录完再手动补进"常见卡点"里——那是你的价值，它替代不了。

**坑三：录进了带真实薪资和客户合同的页面，文档草稿里直接带出真名真数。** 内部系统里这些页面挨得很近，演示时一路点过去就录进去了。解法：**演示前换成测试账号，或者先把数据脱敏**。涉及薪资、客户合同、财务数据的页面，原则上不要交给任何模型处理。文档生成后，全文搜一遍人名和金额，确认都换成了示例值再发出去。

**坑四：文档直接发给新人，他第一步就对不上。** 我录的时候是从浏览器书签直接跳进去的，文档里写的入口新人压根没有；还有个按钮上周刚改了位置。解法：**你自己拿文档当新人，从头走一遍**。走不通的地方改掉，10 分钟的事，省掉的是新人卡住又回来问你的 20 分钟，外加"你给的文档是错的"这个印象。

**坑五：文档写完就再没更新过，半年后全是错的。** 系统改版了没人知道，新人拿着过期文档来问，我还得现场教——回到原点。解法：**文档头部写死"适用版本 + 最后核对日期"**，系统一改版就重录。重录的成本只有第一次的零头，因为流程你已经熟了，演示一遍十分钟。

## 多久能回本

第一次约 40 分钟：装扩展 10 分钟，演示 10 分钟，整理加自己核对一遍 20 分钟。产出第一份能发的操作说明。

之后每来一个新人，直接把文档发过去。原来每教一遍 30-40 分钟，现在你只需要在他卡住时答一句。按每月一两个新人或问询算，一周省 1 小时以上。

**真正的收益是"同样的话不用讲第三遍"。** 而且你讲的三遍版本不一样这种事，从此不会发生了——文档是同一份，改也是改同一处。
